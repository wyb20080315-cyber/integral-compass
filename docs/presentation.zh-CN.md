## 五个真实的非成功结果

均可直接运行 `python examples/failure_cases.py`。Windows 双击 run_failures.cmd。
这些案例有断言；演示预期失败结果后，脚本最终应提示测试通过。

| 类别 | 最小调用 | 预期 |
| --- | --- | --- |
| 深度内全部失败 | integrate("x*exp(x)", 1) | Python None |
| Risch 证明无初等原函数 | integrate("exp(-x**2)") | 字符串 "None, verified by Risch" |
| 超时 | integrate("x", 1, timeout=0.000001) | unknown, timeout: ... |
| 规则不支持 | integrate("Abs(x)", 1) | unknown, unsupported rule: ... |
| 存在未决分支 | integrate("log(x)**2", 2) | unknown, unresolved branches: ... |

超时例子刻意把时限设得比进程启动还短，展示的是时间保护，不说明 x 难以积分。
Risch 例子有用 erf 表示的原函数，这里只讨论初等函数表示。

## 单独解释两个容易混淆的原因

**规则不支持：Abs(x)。** 程序没有实现绝对值/分段积分规则。
数学上它可积，例如原函数 x*Abs(x)/2；失败是软件能力限制。

**未决分支：log(x)**2，深度 2。** 把它看成 log(x)**2 乘 1：

- 对 log(x)**2 求导、对 1 积分，余项 2*log(x) 到了第 2 层，需再展开才能求解。
- 对 1 求导、对 log(x)**2 积分，要先得到后者原函数 v，但基本积分表没有这个直接规则。

第二条不能完成评估，故不能声称两条均失败。深度 3 时第一条继续展开就能成功。
两种原因不是完全独立的：一个未决方向，也可能卡在缺少某个子积分规则。

## 输入错误，不属于数学失败返回值

脚本还展示三种异常：`integrate("1/0", 1)`、`integrate("x", 0)`、
`integrate("x", 1, timeout=0)`。它们分别是非法表达式、非法深度和非法时间。
输入错误抛异常，不能当作无初等解，也不返回 unknown。

## 软件故障和验证失败

没有一个可靠的正常数学输入能保证软件崩溃，因此不编造这种数学例子。
运行 `python examples/failure_cases.py --internal` 可执行明确标为 SIMULATED 的故障注入：

- 模拟工作进程退出：unknown, backend error: ...。
- 模拟进程返回无效数据：同样报告 backend error。
- 模拟候选导数检查失败：unknown, verification failed: ...。

它们用于说明“程序出故障不会谎报无解”，不作为真实数学求解案例上台展示。

## 问答备选

**循环积分怎么办？** `IntegralSolver("exp(x)*sin(x)", 3).solve()` 展示
J=exp(x)*(sin(x)-cos(x))-J，再解一次方程；J=J 不会误当答案。

**谁实现了什么？** 项目实现搜索、展示、循环方程、返回语义和验证流程；
SymPy 提供符号运算、部分分式和 Risch 后端。使用了 OpenAI Codex 协助开发。

**是否处理任意函数？** 不保证。输入语言和算法有明确范围，不支持时诚实说明原因。
